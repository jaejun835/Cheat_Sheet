# 10_로그분석_크리덴셜헌팅

설정 파일, 스크립트, 감사로그, 메모리 안에 남은 크리덴셔/비밀번호를 찾아내는 기법. SUID/sudo/cron처럼 "설정 오류를 이용하는 것"과 달리, "사람이 실수로 남겨둔 흔적"을 찾는 방식이라 실전에서 의외로 잘 통한다.

---

## 1. 감사로그 (auditd/aureport/ausearch)

시스템이 명령어 실행, 로그인, 파일 접근을 기록하는 감사 프레임워크(auditd)가 있다면, 그 로그에 **치명적으로 비밀번호가 평문으로 남아있는 경우**가 많다 (`su`/`sudo` 입력 시 TTY 감사 설정이 키 입력 자체를 기록하는 오설정).

```bash
# 가장 빠른 방법 — TTY 입력 요약
sudo aureport --tty | less

# su/sudo 관련 줄만 색상 강조해서 보기
aureport --tty | grep -E "su |sudo " | sed -E "s,su|sudo,\x1b[1;31m&\x1b[0m,g"

# 원본 감사로그에서 su/sudo 명령어 실행 관련 로그만 직접 grep
grep -RE 'comm="su"|comm="sudo"' /var/log* 2>/dev/null

# ausearch — 특정 키(key)로 달아놓은 규칙만 검색 (rule 설정이 되어있을 때)
sudo ausearch -k <규칙명>
sudo ausearch -i -k <규칙명>   # -i : proctitle 등 hex로 인코딩된 값을 ASCII로 디코딩해서 보여줌

# ausearch 결과를 aureport로 바로 요약로 변환
sudo ausearch -k <규칙명> | aureport
```

회사 내부 root가 직접 입력한 명령어 자체도 `uid=0` 기록으로 남아있는 경우가 있어, 다른 내부망 대역이나 사용자 전환 시도 같은 정보도 함께 노출될 수 있다.

## 2. 일반 로그 파일 전체 훑기 (auditd 없을 때)

```bash
# /var/log 전체를 돌면서 인증/권한전환/sudo 관련 키워드가 있는 파일만 추려내기
for i in $(ls /var/log/* 2>/dev/null); do
  GREP=$(grep "accepted\|session opened\|session closed\|failure\|failed\|ssh\|password changed\|new user\|delete user\|sudo\|COMMAND=\|logs" $i 2>/dev/null)
  if [[ $GREP ]]; then
    echo -e "\n#### Log file: " $i
    grep "accepted\|session opened\|session closed\|failure\|failed\|ssh\|password changed\|new user\|delete user\|sudo\|COMMAND=\|logs" $i 2>/dev/null
  fi
done
```

### 주요 로그 파일의 용도

| 파일 | 내용 |
| --- | --- |
| /var/log/auth.log (Debian계열) / /var/log/secure (RHEL계열) | 로그인, sudo, su 인증 이력 — 제일 먼저 볼 것 |
| /var/log/syslog | 일반 시스템 활동 전반 |
| /var/log/apache2/*, /var/log/nginx/* | 웹서버 액세스/에러 로그, 로그인 폼 제출 값이 GET 파라미터로 그대로 남는 오설정도 종종 발견 |
| /var/log/mysql/* | DB 쿼리 로그, 가끔 평문 비밀번호가 쿼리문에 그대로 남음 |
| /var/log/cron / /var/log/cron.log | 크론재으로 실행된 작업, 스크립트 경로 노출 |
| /var/log/audit/audit.log | auditd 원본 로그, aureport/ausearch로 파싱 |

## 3. journalctl (systemd 저널)

```bash
journalctl --since yesterday --until "2 hours ago"
journalctl -u <서비스명>          # 특정 서비스(apache2, ssh 등) 로그만
journalctl -k                        # 커널 관련몌
journalctl -p 3                      # 우선순위 3(error) 이상만 (0 emergency ~ 7 debug)
journalctl -f                        # 실시간 tail
grep -i "password\|failed\|sudo" <(journalctl -xe)
```

회사 시스템은 개별 로그파일이 아니라 journald(바이너리 형식)만 쓰는 경우가 많아, 이때는 `/var/log/*.log`를 아무리 뒤져도 안 나오고 `journalctl`로만 확인된다.

## 4. 설정 파일 / 데이터베이스 / 스크립트에서 크리덴셔 찾기

```bash
# 설정 파일 자체를 전부 찾기
for l in .conf .config .cnf; do
  echo -e "\n확장자: " $l
  find / -name "*$l" 2>/dev/null | grep -v "lib\|fonts\|share\|core"
done

# 그 안에서 user/password/pass 키워드만 추출 (주석줄 제외)
for i in $(find / -name "*.cnf" 2>/dev/null | grep -v "doc\|lib"); do
  echo -e "\nFile: " $i
  grep "user\|password\|pass" $i 2>/dev/null | grep -v "#"
done

# 데이터베이스 파일들
for l in .sql .db .*db .db*; do
  echo -e "\nDB 확장자: " $l
  find / -name "*$l" 2>/dev/null | grep -v "doc\|lib\|headers\|share\|man"
done

# 스크립트 파일들 (관리자가 자동화 스크립트에 비밀번호를 하드코딩해둔 경우가 흔함)
for l in .sh .py .pl .go .jar .c; do
  echo -e "\n확장자: " $l
  find / -name "*$l" 2>/dev/null | grep -v "doc\|lib\|headers\|share"
done

# 웹루트(/var/www) 집중 탐색 — 상용대버전 없이 전체 필터시스템을 다 뒤지면 결과가 너무 많으니, 웹루트부터 좌혀서 범위를 보통 좌혀놓고 시작을
find /var/www -type f \( -name "*.php" -o -name "*.env" -o -name "config*" \) 2>/dev/null | xargs grep -il "password\|db_pass\|api_key" 2>/dev/null

# 홈 디렉터리와 /root에서 공개 SSH 키 문자열 검색
grep -RniE 'ssh-(rsa|ed25519|ecdsa)' /home /root 2>/dev/null

# 홈 디렉터리와 /root에서 개인키 헤더 검색
grep -RniE 'BEGIN (OPENSSH|RSA|EC|DSA) PRIVATE KEY' /home /root 2>/dev/null

# 개인키 파일명(id_rsa, id_ed25519 등)을 직접 검색
find /home /root -type f \
  \( -name 'id_rsa' -o -name 'id_ed25519' -o -name 'id_ecdsa' -o -name 'id_dsa' \) \
  -ls 2>/dev/null

# 현재 사용자가 읽을 수 있는 개인키 파일만 검색
find /home /root -type f \
  \( -name 'id_rsa' -o -name 'id_ed25519' -o -name 'id_ecdsa' -o -name 'id_dsa' \) \
  -readable -print 2>/dev/null

# 공개 RSA SSH 키 문자열 검색
grep -rn 'ssh-rsa' /home/* /root 2>/dev/null

# 개인키 문자열 검색
grep -rn 'PRIVATE KEY' /home/* /root 2>/dev/null
```

### 파일시스템 전체에서 키워드 검색 (속도용)

```bash
# 파일명에 passw/pwd 가 들어간 것만 (이름으로만 매칭, 내용은 안 봈)
find / -exec ls -lad $PWD/* "{}" 2>/dev/null \; | grep -i -I "passw\|pwd"

# locate 로 빠르게 (locate DB가 최신이어야 함)
locate password
locate -i pass

# 내용까지 포함해서 전역 검색 (결과 많음, 특정 디렉토리로 좌혀서 스키텀 없이 실행게 권장)
grep --color=auto -rnw -iIe "PASSW|PASSWD|PASSWORD|PWD" --color=always /var/www 2>/dev/null
```

## 5. 프로세스 메모리에서 크리덴셔 덤핑 (root 권한 필요)

로그인 중인 사용자의 프로세스 메모리에 평문 비밀번호가 남아있는 경우(GNOME Keyring, VSFTPD, Apache Basic Auth 등)가 많다.

```bash
# mimipenguin — 알려진 패턴(gcore로 프로세스 덤프 뒤 문자열 추출)
git clone https://github.com/huntergregal/mimipenguin
sudo python3 mimipenguin.py
sudo bash mimipenguin.sh

# LaZagne — Linux에서도 브라우저/시스템 저장 크리덴셔 복구
sudo python3 laZagne.py all
python3 laZagne.py browsers   # Firefox 등 브라우저 저장분만

# 수동으로 /proc 덤프해서 문자열 추출
ps -eo pid,comm
cat /proc/<PID>/maps
gcore <PID>              # 프로세스 메모리 덤프
strings core.<PID> | grep -i "pass\|pwd"

# Firefox 저장 크리덴셔 직접 확인
ls -l ~/.mozilla/firefox/ | grep default
cat ~/.mozilla/firefox/<프로필>/logins.json | jq .
# key4.db / logins.json 조합은 firefox_decrypt.py 로 복호화
```

## 6. shell history / bash 설정 파일

```bash
cat ~/.bash_history
cat ~/.zsh_history
cat ~/.mysql_history
cat ~/.psql_history
find / -type f \( -name "*_history" -o -name "profile" -o -name "*bashrc" \) -exec ls -l {} \; 2>/dev/null
```

명령어 자체에 `mysql -u root -p'비밀번호'`처럼 비밀번호가 인자로 그대로 들어간 혼적이 흔하다.

## 팁

- 로그 읽기에는 `adm` 그룹 권한이 가장 유용 — `id`로 이 그룹 소속 여부부터 먼저 확인
- 이상한 로그일수록(내용이 남들수록) 흥미로운 정보일 확률이 높다
- `find / ...` 스타일의 전체 파일시스템 검색은 결과가 너무 많을 수 있으니, 가능하면 웹루트/홈디렉토리처럼 범위를 미리 좌혀놓고 시작
