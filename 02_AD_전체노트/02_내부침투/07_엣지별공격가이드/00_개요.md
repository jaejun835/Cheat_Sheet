# 00_개요

## 노드 타입 구분

BloodHound에서 엣지를 발견하면 대상 노드 타입을 먼저 확인해야 한다. 같은 엣지라도 대상 타입에 따라 공격 방법이 완전히 달라진다.

| 아이콘 | 색상 | 타입 | 설명 |
| --- | --- | --- | --- |
| 사람 | 초록 | User | 사용자 계정 / 서비스 계정 |
| 모니터 | 빨강 | Computer | 워크스테이션 / 서버 / DC |
| 여러명 | 노랑 | Group | 보안 그룹 / 배포 그룹 |
| 지구본 | 초록-파랑 | Domain | 도메인 루트 오브젝트 |
| 폴더 | 하늘색 | OU | Organizational Unit |
| 기어 | 주황 | GPO | Group Policy Object |
| 인증서 | 보라 | CertTemplate | ADCS 인증서 템플릿 |
| 빌딩 | 보라 | EnterpriseCA | ADCS Enterprise CA |

---

## 공격 방식 분류

ACL 기반 공격은 사용하는 프로토콜에 따라 단계가 나뉜다. 방화벽 제약 상황에서 어느 포트가 열려있는지에 따라 사용 가능한 공격이 달라진다.

| 단계 | 프로토콜 | 포트 | 역할 | 주요 도구 |
| --- | --- | --- | --- | --- |
| 1단계 — 속성 변경 | LDAP | 389 / 636 | ACL 수정 / 그룹 추가 / SPN 설정 / RBCD 설정 / 패스워드 변경 | bloodyAD, impacket-dacledit, impacket-owneredit, PowerView |
| 2단계 — 티켓 발급 | Kerberos | 88 | TGT / TGS 요청, Kerberoasting, PKINIT 인증 | impacket-getST, GetUserSPNs, Rubeus, certipy |
| 3단계 — 실제 접근 | SMB / WinRM | 445 / 5985 | 원격 코드 실행 / 해시 덤프 | psexec, secretsdump, evil-winrm, nxc |
| 보조 — 인증서 | ADCS | 443 / 80 | ESC 공격 / PKINIT → TGT | certipy, pywhisker |
