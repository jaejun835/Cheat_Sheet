## Linux 파일 권한

### 기본 구조

```
-rwxr-xr--  1  root  wheel  4096  Jan 1 12:00  file.txt
│└─┤└─┤└─┘     │      │
│  │  │  │     │      └── 그룹명
│  │  │  │     └───────── 소유자명
│  │  │  └─────────────── others 권한 (r--)
│  │  └────────────────── group 권한  (r-x)
│  └───────────────────── owner 권한  (rwx)
└──────────────────────── 파일 타입
```

### 파일 타입

```
-  일반 파일
d  디렉터리
l  심볼릭 링크
b  블록 디바이스
c  문자 디바이스
s  소켓
p  파이프 (FIFO)
```

### 권한 비트

```
r (read)    읽기   = 4
w (write)   쓰기   = 2
x (execute) 실행   = 1

rwx = 7 (4+2+1)
rw- = 6 (4+2)
r-x = 5 (4+1)
r-- = 4
-wx = 3 (2+1)
-w- = 2
--x = 1
--- = 0
```

### 예시 해석

```
-rwxr-xr--  = 754
  rwx = 7 (소유자: 읽기+쓰기+실행)
  r-x = 5 (그룹: 읽기+실행)
  r-- = 4 (others: 읽기만)

-rw-r--r--  = 644  (일반 파일의 기본값)
drwxr-xr-x  = 755  (디렉터리의 기본값)
-rwx------  = 700  (소유자만 모든 권한)
-rw-------  = 600  (개인키 id_rsa의 권한)
```

## 특수 권한 비트

### SUID (Set User ID) — 4000

```
-rwsr-xr-x  (소유자의 x 위치에 s)
-rwSr-xr-x  (S = SUID 있지만 실행 권한 없음)

숫자: 4755 (SUID + rwxr-xr-x)

의미: 이 파일을 실행하면 파일 소유자 권한으로 실행됨
→ root 소유 SUID = 누가 실행해도 root 권한으로 실행
→ 권한상승의 핵심 벡터
```

```bash
# SUID 파일 찾기
find / -perm -4000 -type f 2>/dev/null
find / -perm -u=s -type f 2>/dev/null

# 확인
ls -la /bin/passwd
# -rwsr-xr-x 1 root root ...  ← s 가 있으면 SUID
```

### SGID (Set Group ID) — 2000

```
-rwxr-sr-x  (그룹의 x 위치에 s)

의미: 실행 시 파일 그룹 권한으로 실행됨
     디렉터리에 설정 시 새로 생성되는 파일이 해당 그룹 소유
```

### Sticky Bit — 1000

```
drwxrwxrwt  (others의 x 위치에 t)

의미: 디렉터리에서 자신이 소유한 파일만 삭제 가능
     /tmp 에 적용되는 것이 대표적
```

## chmod 명령어

```bash
# 숫자로 설정
chmod 755 file.txt    # rwxr-xr-x
chmod 644 file.txt    # rw-r--r--
chmod 600 id_rsa      # rw------- (개인키)
chmod 4755 binary     # SUID + rwxr-xr-x
chmod +s binary       # SUID 추가
chmod -s binary       # SUID 제거

# 기호로 설정
chmod u+x file.txt    # 소유자에게 실행 권한 추가
chmod g-w file.txt    # 그룹의 쓰기 권한 제거
chmod o+r file.txt    # others에게 읽기 권한 추가
chmod a+x file.txt    # 모두에게 실행 권한 추가
chmod u=rwx,g=rx,o= file.txt
```

## chown / chgrp

```bash
chown user:group file.txt      # 소유자와 그룹 변경
chown user file.txt            # 소유자만 변경
chgrp group file.txt           # 그룹만 변경
chown -R user:group directory/ # 재귀적으로
```

## umask

새로 생성되는 파일/디렉터리의 기본 권한 마스크

```
umask 022  → 파일: 644 (666-022), 디렉터리: 755 (777-022)
umask 027  → 파일: 640, 디렉터리: 750
umask 000  → 파일: 666, 디렉터리: 777 (위험)
```

## SSH 개인키 권한

SSH는 개인키 파일이 소유자 외에게 읽기 권한이 있으면 아예 키 사용을 거부한다. `chmod 600`이 관용구처럼 쓰이는 이유가 바로 이 정책 때문이다. GTFOBins나 특권 파일 읽기로 얻은 키를 로컬에 저장할 때도 동일하게 적용된다.

```bash
# 권한이 너무 열려 있을 때 뜨는 경고 (일부 발췌)
@ WARNING: UNPROTECTED PRIVATE KEY FILE! @
Permissions 0644 for '<키파일>' are too open.
It is required that your private key files are NOT accessible by others.
This private key will be ignored.
Load key "<키파일>": bad permissions

# 해결
chmod 600 <키파일>   # 소유자만 읽기/쓰기
chmod 400 <키파일>   # 소유자 읽기 전용 (더 엄격, 일부 AWS .pem 관례)

# .ssh 디렉터리 자체도 권한이 너무 열려있으면 같은 문제 발생
chmod 700 ~/.ssh
```

## ACL (Access Control List) — getfacl / setfacl

전통적인 owner/group/other 권한 모델로는 표현 못 하는 세밀한 접근 제어를 ACL이 추가로 덧씌운다. **`ls -l`만 보고 "이 파일은 안전하다"고 판단하면 안 되는 대표적인 이유**다 — 권한 비트가 아무리 restrictive해도 ACL이 별도로 특정 유저/그룹에게 접근을 열어줄 수 있다.

`ls -la` 결과 권한 끝에 `+`가 붙어 있으면 그 파일/디렉터리에 ACL이 걸려 있다는 신호다.

```bash
# ACL 확인
getfacl <파일경로>
# ls -la 에서 + 표시 확인
ls -la <디렉터리>
# 예: -rw-r-----+ 1 root root ... file   ← 맨 끝 + 가 ACL 존재 신호

# ACL 걸린 파일 재귀 검색
getfacl -R -s -p / 2>/dev/null | grep -B3 "^# file:"

# ACL 설정/제거 (참고용 — 공격자가 직접 걸 일은 적음, 주로 이미 걸린 걸 발견하는 용도)
setfacl -m u:<유저>:rw <파일>
setfacl -b <파일>   # 모든 ACL 제거
```

## chattr / lsattr — 파일 속성 (immutable / append-only)

rwx나 ACL과 완전히 다른 레이어다. ext2/3/4, 부분적으로 XFS/Btrfs에서 파일시스템 inode 자체에 걸리는 속성이며, **`+i`(immutable)가 걸리면 root라도 수정·삭제·이름변경이 불가능하다**. 방어 관점에서는 `/etc/passwd`, `/etc/shadow`, 설정파일 보호에 쓰이고, 공격/탐지 관점에서는 "권한상 root인데 왜 이 파일이 안 고쳐지지?"를 설명해주는 원인이 된다.

```bash
# 속성 확인
lsattr <파일>
# ----i---------e--- file.txt   ← i 가 있으면 immutable

# 즉시 확인해볼 만한 경로
lsattr -R /etc/ssh /etc/passwd /etc/shadow 2>/dev/null

# immutable 걸려 있으면 수정/삭제 시도해도 다음처럼 실패
rm file.txt
# rm: cannot remove 'file.txt': Operation not permitted

# 해제 (root 또는 CAP_LINUX_IMMUTABLE 권한 필요)
chattr -i <파일>

# CAP_LINUX_IMMUTABLE capability를 가진 바이너리가 있으면
# root가 아니어도 immutable 우회 가능 (07_capabilities 참고)
getcap -r / 2>/dev/null | grep -i immutable
```

## Windows 권한 (icacls)

```bash
:: 권한 확인
icacls C:\path\to\file
icacls C:\path\to\directory

:: 출력 예시
:: C:\Temp\file.exe BUILTIN\Administrators:(F)
::                  NT AUTHORITY\SYSTEM:(F)
::                  BUILTIN\Users:(RX)
::                  Everyone:(R)
```

### 권한 코드

```
F   Full Control (모든 권한)
M   Modify (수정 - R, W, X 포함)
RX  Read and Execute
R   Read
W   Write
D   Delete
X   Execute/Traverse

(OI) Object Inherit (하위 파일에 상속)
(CI) Container Inherit (하위 폴더에 상속)
(IO) Inherit Only
(NP) No Propagate Inherit
```

```bash
:: 권한 부여
icacls C:\file.exe /grant Everyone:F
icacls C:\file.exe /grant "BUILTIN\Users":(RX)

:: 권한 제거
icacls C:\file.exe /remove Everyone

:: 소유자 변경
takeown /f C:\file.exe
icacls C:\file.exe /grant Administrators:F
```

## Windows 서비스 권한 (sc / accesschk)

```bash
:: 서비스 상세 정보
sc qc ServiceName
:: BINARY_PATH_NAME  = 실행 파일 경로
:: START_TYPE        = 시작 유형(2=자동, 3=수동, 4=비활성)
:: SERVICE_START_NAME = 실행 계정(LocalSystem = SYSTEM 권한)

:: 서비스 ACL 확인(accesschk.exe)
accesschk.exe -uwcqv "Authenticated Users" ServiceName
accesschk.exe -uwcqv Everyone ServiceName

:: 주요 서비스 권한
:: SERVICE_ALL_ACCESS     = 모든 권한
:: SERVICE_CHANGE_CONFIG  = 설정 변경 가능 → 바이너리 경로 교체
:: SERVICE_START          = 시작 가능
:: SERVICE_STOP           = 정지 가능
```

## Linux /etc/passwd 형식

```
root:x:0:0:root:/root:/bin/bash
│    │ │ │ │    │     └── 로그인 쉘
│    │ │ │ │    └──────── 홈 디렉터리
│    │ │ │ └───────────── GECOS (이름 정보)
│    │ │ └─────────────── GID (기본 그룹 ID)
│    │ └───────────────── UID (사용자 ID)
│    └─────────────────── 패스워드 (x = shadow 파일 참조)
└──────────────────────── 사용자명

UID 0    = root
UID 1-99 = 시스템 계정
UID 1000+ = 일반 사용자
```

## Linux /etc/shadow 형식

```
root:$6$salt$hash:18000:0:99999:7:::
│    │            │     │ │     └── 비활성화까지 경고 일수
│    │            │     │ └──────── 패스워드 만료까지 최대 일수
│    │            │     └────────── 패스워드 변경 후 최소 유지 일수
│    │            └──────────────── 마지막 변경일 (1970-01-01 기준)
│    └───────────────────────────── 해시 ($6 = SHA-512)
└────────────────────────────────── 사용자명

해시 알고리즘:
$1  = MD5
$2a = Blowfish
$5  = SHA-256
$6  = SHA-512 (현대 Linux 기본)
```

```bash
# shadow 크랙
hashcat -m 1800 shadow.txt rockyou.txt    # SHA-512 ($6)
hashcat -m 500 shadow.txt rockyou.txt     # MD5 ($1)
john shadow.txt --wordlist=rockyou.txt
```
