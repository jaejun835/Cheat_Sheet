## Burp Suite 실행 실패: UnsupportedClassVersionError

```
Error: LinkageError occurred while loading main class burp.StartBurp
java.lang.UnsupportedClassVersionError: burp/StartBurp has been compiled by a more recent version
of the Java Runtime (class file version 65.0), this version of the Java Runtime only recognizes
class file versions up to 55.0
```

**원인**: 최신 Burp는 Java 21(class version 65)로 컴파일되어 있는데, 시스템 기본 java가 Java 11(class version 55)로 잡혀 있어서 발생.

```bash
# 설치된 Java 버전들 확인
java -version
update-alternatives --list java

# Java 21이 이미 설치되어 있으면 기본값만 전환
sudo update-alternatives --config java
# 목록에서 java-21-openjdk 경로 번호 입력

# 없으면 신규 설치
sudo apt update
sudo apt install openjdk-21-jdk -y
sudo update-alternatives --config java

# 확인
java -version   # openjdk version "21..." 나오면 성공

# 다시 실행
burpsuite &
```

실행 시 "Your JRE appears to be version 21.x from Debian... Burp has not been fully tested" 경고가 뜨는데, 이건 단순 경고일 뿐 실행은 정상적으로 된다. "Don't show again" 체크하고 OK 누르면 됨.

## Burp: 가이드 없이는 안 나오는 화면을 눈으로 보기 (Show response in browser)

TRACK/TRACE같은 브라우저가 직접 보낼 수 없는 메서드로 받은 응답(HTML)을 실제 렌더링된 화면으로 확인하고 싶을 때 쓸 수 있는 기능.

1. Repeater/Proxy의 **Response** 패널에서 우클릭
2. **"Show response in browser"** 선택
3. Burp가 임시 URL(예: `http://127.0.0.1:포트/랜덤문자열`) 생성
4. 그 URL을 복사해서 프록시 통하는 브라우저(또는 Burp 내장 브라우저)에 붙여넣으면 HTML이 그대로 렌더링됨

**주의**: 이 방법은 수동 조작이 들어간 요청(TRACK, 커스텀 헤더 등)의 응답을 **눈으로 보는 용도**일 뿐이다. 이 화면에서 폼(업로드 등)을 직접 제출하면, 그 제출 요청은 커스텀 헤더없이 진짜 서버로 나가므로 다시 막힐 수 있다. 실제 제출은 Repeater에서 수동으로 요청을 만들어 보내는 게 안전함.

## zsh/bash에서 `!`가 계속 에러 내는 문제 (hydra, curl 등)

`!`는 쉘의 히스토리 확장(history expansion) 문자라서, 큰따옴표(`"`) 안에 있어도 명령어가 깨진다. hydra의 실패 메시지 문자열(`Invalid Credentials!`)이나 curl 페이로드 안에 `!`가 있을 때 자주 발생한다.

```bash
# 에러 나는 경우
hydra ... "/login.php:...:Invalid Credentials!"
zsh: event not found: !

# 해결 1: 큰따옴표 대신 작은따옴표로 전체를 감싼다 (작은따옴표 안에서는 ! 이 문자 그대로 취급됨)
hydra ... '/login.php:...:Invalid Credentials!'

# 해결 2: 백슬래시로 이스케이프
hydra ... "/login.php:...:Invalid Credentials\!"

# 해결 3: 현재 쉘 세션에서 히스토리 확장 자체를 끄기
set +H
```

## 워드리스트 크기를 시간 예산에 맞춰 고르기

rockyou.txt(약 1,400만 개) 전체를 브루트포스에 그대로 돌리면 초당 800개 시도 기준으로 **약 300시간**이 걸릴 수 있다. 시간 제한이 있는 상황에서는 절대 전체를 그대로 돌리지 않는다.

```bash
# 상위 N개만 잘라서 사용
head -n 10000 /usr/share/wordlists/rockyou.txt > /tmp/small.txt

# seclists에 이미 정리된 상위 빈도 리스트 활용
/usr/share/seclists/Passwords/Common-Credentials/xato-net-10-million-passwords-1000.txt
/usr/share/seclists/Passwords/Common-Credentials/Pwdb_top-1000.txt

# 스레드 수를 올려서 속도 자체를 높이는 것도 병행
hydra ... -t 64
```

스레드 수(`-t`)와 워드리스트 크기(개수)를 곱한 값이 대략 예상 소요시간을 결정한다. 시도 전에 항상 "이 조합이 현실적인 시간 안에 끝나는가"를 먼저 계산해보는 습관이 필요하다.

## 서비스 전용 워드리스트가 존재하는 이유

Tomcat, FTP, MySQL, SNMP 같은 서비스는 사람이 임의로 정하는 계정이 아니라 설치 매뉴얼/기본 설정에서 나온 정해진 패턴의 기본 계정을 쓰는 경우가 많다 (tomcat:s3cret, admin:admin 등). rockyou.txt처럼 사람이 실제로 쓰는 비밀번호 모음보다, 이런 소프트웨어별 기본값만 모은 전용 리스트가 훨씬 적중률이 높고 빨리 끝난다.

```bash
# Tomcat 전용
find /usr/share/seclists -iname "*tomcat*"
/usr/share/seclists/Passwords/Default-Credentials/tomcat-betterdefaultpasslist.txt
/usr/share/metasploit-framework/data/wordlists/tomcat_mgr_default_userpass.txt
/usr/share/metasploit-framework/data/wordlists/tomcat_mgr_default_users.txt
/usr/share/metasploit-framework/data/wordlists/tomcat_mgr_default_pass.txt

# 다른 서비스도 같은 패턴 (SecLists Default-Credentials 디렉터리)
find /usr/share/seclists/Passwords/Default-Credentials -type f
# ftp-betterdefaultpasslist.txt, mysql-betterdefaultpasslist.txt,
# snmp-community-strings.txt 등
```

### Hydra vs Metasploit 브루트포스 모듈 — 선택 기준

- Metasploit 모듈 (auxiliary/scanner/http/tomcat_mgr_login 등): 서비스별 로그인 방식 차이(리다이렉트, 401 응답 패턴 등)를 이미 처리해둔 — 빠르게 정확히 돌리고 싶을 때
- Hydra: 더 가밝고 빠르지만, 서비스가 리다이렉트를 쓰면 실패 조건 패턴을 직접 맞춰야 할 수 있음

```bash
hydra -L users.txt -P passwords.txt <IP> -s 8080 http-get /manager/html   # ← 수정
```
