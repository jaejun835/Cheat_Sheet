# 11_암호화디스크

# 해시 타입별 크랙 — 암호화 디스크 (BitLocker)

Windows 전체 디스크 암호화. VHD 가상 디스크나 USB 이미지로 자주 나온다. 해시를 뽑아 오프라인 크랙한 뒤, 리눅스에서는 dislocker 로 복호화해서 마운트하는 흐름이다.

---

## 개념

BitLocker 는 볼륨을 실제 암호화 키로 잠그고, 그 키를 다시 VMK 로 암호화해 둔다. VMK 는 보호기마다 따로 암호화된 사본이 저장된다. 사용자 비밀번호로 한 벌, 48자리 복구키로 한 벌이다. 그래서 bitlocker2john 이 해시를 여러 개 뽑는다. 복구키는 랜덤 48자리라 일부를 알지 않는 한 크랙이 비현실적이고, 비밀번호 쪽만 노린다.

---

## 1. 해시 추출

```bash
bitlocker2john -i <파일>.vhd > bitlocker.hashes

# 출력 4줄
# $bitlocker$0$ / $bitlocker$1$  → 사용자 비밀번호
# $bitlocker$2$ / $bitlocker$3$  → 복구키 (48자리 랜덤, 크랙 비현실적)

# 비밀번호 해시만 분리
grep 'bitlocker\$0' bitlocker.hashes > bitlocker.hash
```

실행 중 `Invalid version, looking for a signature with valid version...` 이 찍히는 건 앞쪽에서 가짜 시그니처를 잡았다가 넘어가는 것이라 무시한다. 뒤에 `VMK encrypted with User Password found` 가 나오면 정상이다.

---

## 2. 크랙

hashcat 모드 22100 이다. 키 유도 반복이 약 100만 번이라 매우 느리다. CPU 기준 초당 수백 개 수준이다.

```bash
hashcat -a 0 -m 22100 bitlocker.hash /usr/share/wordlists/rockyou.txt
hashcat -m 22100 bitlocker.hash --show

# john 도 가능
john --format=bitlocker --wordlist=/usr/share/wordlists/rockyou.txt bitlocker.hash
```

주의: 커널 최소 길이가 6 이라 6자 미만 후보는 Rejected 로 버려진다. BitLocker 비밀번호는 정책상 최소 8자라 실제로는 문제 없다.

---

## 3. 리눅스에서 마운트 (dislocker)

VHD → 루프 장치 → dislocker 복호화 → NTFS 마운트, 세 겹을 차례로 벗긴다.

```bash
sudo apt install dislocker
sudo mkdir -p /media/bitlocker /media/bitlockermount

# 1) VHD 를 루프 장치로 (-P: 내부 파티션 인식, --show: 잡힌 장치 출력)
sudo losetup -f -P --show <파일>.vhd
lsblk
# → loop0 아래 loop0p1 같은 파티션 이름 확인

# 2) 복호화 (-u 바로 뒤에 공백 없이 비밀번호)
sudo dislocker /dev/<파티션> -u'<비번>' -- /media/bitlocker
# 복구키를 알면: -p<48자리복구키>
sudo ls -la /media/bitlocker
# → dislocker-file 이 생기면 성공 (복호화된 볼륨 이미지)

# 3) 볼륨 이미지를 NTFS 로 마운트
sudo mount -o loop /media/bitlocker/dislocker-file /media/bitlockermount
sudo ls -la /media/bitlockermount
```

주의: 파티션 번호는 반드시 lsblk 로 확인한다. HTB 모듈 예시는 `loop0p2` 인데 실습 이미지는 `loop0p1` 하나뿐이었다. 없는 장치를 넣으면 dislocker 가 바로 실패한다.

주의 2: `/media/bitlocker` 를 일반 사용자로 ls 하면 Permission denied 가 난다. dislocker 를 root 로 띄워 FUSE 마운트했기 때문에 root 만 접근할 수 있다. 실패한 게 아니니 sudo 로 확인한다.

주의 3 (WSL2): 3) 에서 `unknown filesystem type 'ntfs3'` 이 나면 WSL2 커널에 ntfs3 모듈이 없는 것이다. 복호화는 이미 끝났으니 FUSE 드라이버를 직접 지정한다.

```bash
sudo mount -t ntfs-3g -o loop /media/bitlocker/dislocker-file /media/bitlockermount
```

---

## 4. 언마운트

마운트한 역순으로 푼다.

```bash
sudo umount /media/bitlockermount
sudo umount /media/bitlocker
sudo losetup -d /dev/<loopN>
losetup -a     # 아무것도 안 나오면 정리 완료
```

주의: `losetup -d` 를 빼먹으면 다음에 같은 VHD 를 잡을 때 loop1, loop2 로 또 붙어서 같은 이미지가 여러 장치에 중복으로 걸린다. `losetup -a` 로 남은 게 없는지 확인한다.

---

## 5. Windows 에서 마운트

.vhd 를 더블클릭하면 마운트되고, 잠긴 BitLocker 볼륨을 더블클릭하면 비밀번호 창이 뜬다. 명령줄로는 이렇게 한다.

```powershell
Mount-DiskImage -ImagePath "<경로>\<파일>.vhd"
manage-bde -unlock <드라이브>: -Password
```

---

## 팁

- 해시 4개 중 `$bitlocker$0$` 만 크랙한다. 복구키는 시도할 가치가 없다
- 22100 은 느리다. rockyou 전체보다 정황 기반 워드리스트(회사명, 계절+연도 등)를 먼저 돌린다
- 리눅스 마운트가 안 되면 losetup, dislocker, mount 중 어느 단계에서 막혔는지 lsblk 와 sudo ls 로 하나씩 확인한다
- 크랙한 비밀번호는 다른 서비스에 재사용 시도할 것
