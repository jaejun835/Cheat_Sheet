# 발견 경로 공략

디렉터리/파일 탐색(03)으로 찾은 경로를 어떻게 공략하는지. 상태코드로 1차 판단하고, 경로별로 노리는 게 다르다.

---

## 상태코드별 대응

```
200  정상 접근. 내용 바로 확인
301  영구 리다이렉트. 어디로 튕기는지 확인
302  임시 리다이렉트. 로그인 없으면 튕기는 경우 많음 - 인증 후 재시도
401  인증 필요. 크리덴셜 확보 후 반드시 재시도
403  존재하지만 접근 차단. 스킵 말고 우회 시도
       우회: 끝에 / 추가, 대소문자 변환, X-Forwarded-For: 127.0.0.1 헤더
500  서버 에러. 입력 처리 중 터진 것 - 취약점 힌트. 파라미터 조작 시도
404  없음. 스킵
```

## 최우선 경로

### /admin

- 관리자 패널. 302 로 튕기면 로그인 필요 또는 인증 우회 시도
- 크리덴셜 확보되면 바로 재접근. 파일 업로드, 유저 관리 기능 확인
- 일반 유저 토큰으로 admin 엔드포인트 접근 가능한지 반드시 시도 (인가 취약점)

### /.env

- Laravel/Node/Django 등의 DB 접속 정보, APP_KEY, JWT_SECRET, API_KEY 직접 노출
- 발견 즉시 전체 확인. 크리덴셜 SSH/DB 재사용 전부 시도

### /.git

- 소스코드 전체 복원 가능
- 외부 접근되면 덤프: `git-dumper http://<IP>/.git/ ./dump`
- 내부 쉘 후: `git log --oneline --all`, `git show <HASH>:<파일>` 로 삭제된 크리덴셜 복원
- 커밋에 테스트용으로 박은 비번이 운영 계정에 그대로 쓰이는 경우 많음
- 도메인 패턴으로 검색: `grep -ir "@<대상도메인>" 2>/dev/null`

### /upload, /uploads

- 파일 업로드 → 웹셸 → RCE 시도
- 확장자 필터 우회: .php5 .phtml .phar .php.jpg 등
- Content-Type 변조: image/jpeg 로 두고 PHP 삽입
- 업로드 후 /storage, /uploads, /files 에서 직접 접근 가능한지 확인

### /login

- SQLi 시도. ' 입력 후 500/DB 에러 뜨면 가능성 높음
- 기본 크리덴셜: admin/admin, admin/password, root/root
- rate limit, 계정 잠금 정책 확인 후 브루트포스

### /api

- JS 파일과 함께 엔드포인트 구조 파악
- v1/v2 버전 차이 확인. 구버전에 인증 없이 접근되는 경우 있음
- 일반 토큰으로 admin 엔드포인트 접근 시도 (인가 취약점)
- `grep -RhoE "/api/[A-Za-z0-9_./?&=%:{}-]+" *.js | sort -u`

## 중요 경로

### /js

- app.js, admin.js 다운받아 API 엔드포인트 전부 추출
- 하드코딩된 API 키, 시크릿, 숨겨진 라우트, 주석 확인

### /backup, /config

- 소스코드, DB 덤프, 설정 파일 노출 가능성
- .zip .tar .gz .sql .bak .old 로 직접 접근 시도
- config.php, config.yml, settings.py 등 추측 접근
- 사이트명/도메인명 기반으로 파일명 추측

### /phpinfo.php

- PHP 버전, 설치 경로, 모듈, 환경변수 전체 노출
- disable_functions 확인 → 웹셸에서 쓸 함수 파악
- 버전 확인 후 CVE 탐색

### /robots.txt, /sitemap.xml

- 숨기려고 명시한 경로가 오히려 힌트
- Disallow 항목 전부 직접 접근
